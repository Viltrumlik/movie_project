# Movie Project

A movie catalog backend built with Django 5.1 and Django REST Framework. It provides a JWT-secured REST API for movies, reviews, genres, people and countries, with interactive Swagger/ReDoc documentation and a Django admin styled with Unfold. A server-rendered web front end is started but not finished.

## Status

Partially complete.

- **Working:** the REST API, JWT authentication, the API docs and the admin panel.
- **Early stage:** the web pages. The home page (`/`) is a static MDB UI Kit mock-up that does not list movies from the database yet, the movie detail view (`/movie/<id>/`) is unfinished, and the login/register templates are not connected to any URL.
- The data model in `config/models.py` also defines collections, watch lists, seasons and episodes, awards, subtitles, reports and notifications. Most of these do not have API endpoints yet.

## Features

- **Authentication:** registration endpoint plus SimpleJWT access/refresh/verify tokens (60-minute access tokens, rotating refresh tokens); session login for the browsable API
- **Movies API:** full CRUD with search on title and description, ordering by `release_date`, `rating` or `created_at`, and page-number pagination (10 per page, `?page_size=` up to 100)
- **Reviews:** users post reviews with a rating; the movie's average rating is recalculated when a review is created; only the author can edit or delete a review
- **Genres, people (actors, directors, writers, producers) and countries:** CRUD endpoints
- **Permissions:** apart from registration and the token endpoints, every endpoint requires a logged-in user; only staff users can create, update or delete movies, genres, people and countries
- **Rate limiting:** 100 requests/day for anonymous users, 1000/day for authenticated users
- **Upload validation:** trailers must be MP4 or MOV, extra movie images must be JPEG or PNG (at least 300×450); file types are checked with `python-magic`, size limit 10 MB
- **Email notification:** when a movie is created through `/api/movies/`, every user with an email address gets a notification (requires SMTP settings)
- **API docs:** Swagger UI and ReDoc generated by `drf-yasg`
- **Admin:** Django admin with the Unfold theme
- **File cleanup:** `django-cleanup` deletes replaced or orphaned uploaded files

## Tech stack

- Python 3.10+, Django 5.1
- Django REST Framework, djangorestframework-simplejwt, drf-yasg, django-filter
- django-unfold, django-cleanup, Pillow, python-magic

## Getting started

### Prerequisites

- Python 3.10 or newer and pip
- The `libmagic` system library, required by `python-magic`:
  - macOS: `brew install libmagic`
  - Debian/Ubuntu: `sudo apt install libmagic1`

### Installation

```bash
git clone https://github.com/Viltrumlik/movie_project.git
cd movie_project
python3 -m venv venv
source venv/bin/activate          # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

### Configuration

Settings are in `movie_project/settings.py`; the project does not read environment variables. It is set up for local development (`DEBUG = True`, a hard-coded development `SECRET_KEY`, SQLite). To enable email notifications, replace the placeholder SMTP values:

```python
EMAIL_HOST_USER = "your-email@gmail.com"
EMAIL_HOST_PASSWORD = "your-app-password"
```

Before deploying anywhere public, set your own `SECRET_KEY`, `DEBUG = False` and `ALLOWED_HOSTS`.

### Run

```bash
python manage.py migrate
python manage.py createsuperuser
python manage.py runserver
```

| URL                              | Description          |
|----------------------------------|----------------------|
| http://127.0.0.1:8000/admin/     | Admin panel          |
| http://127.0.0.1:8000/swagger/   | Swagger UI           |
| http://127.0.0.1:8000/redoc/     | ReDoc                |
| http://127.0.0.1:8000/api/       | Browsable API        |

### Run with Docker

```bash
docker build -f dockerfile -t movie_project .
docker run -p 8000:8000 movie_project
```

The image runs the Django development server on port 8000.

## API usage

| Method                 | Endpoint                                       | Notes                                  |
|------------------------|------------------------------------------------|----------------------------------------|
| POST                   | `/api/register/`                               | `username`, `email`, `password`, `password2` |
| POST                   | `/api/token/`                                  | Returns `access` and `refresh` tokens  |
| POST                   | `/api/token/refresh/`                          | Exchange a refresh token               |
| POST                   | `/api/token/verify/`                           | Check a token                          |
| GET, POST              | `/api/movies/`                                 | `?search=`, `?ordering=`, `?page=`, `?page_size=` |
| GET, PUT, PATCH, DELETE | `/api/movies/<id>/`                           | Writes are staff-only                  |
| GET, POST              | `/api/reviews/`                                |                                        |
| GET, PUT, PATCH, DELETE | `/api/reviews/<id>/`                          | Writes are author-only                 |
| GET, POST              | `/api/genres/`, `/api/persons/`, `/api/countries/` | Writes are staff-only              |
| GET, PUT, DELETE       | `/api/genres/<id>/`, `/api/persons/<id>/`, `/api/countries/<id>/` | Writes are staff-only |

Example:

```bash
# Get a token pair
curl -X POST http://127.0.0.1:8000/api/token/ \
  -H "Content-Type: application/json" \
  -d '{"username": "<username>", "password": "<password>"}'

# Call the API with the access token
curl "http://127.0.0.1:8000/api/movies/?search=godfather&ordering=-rating" \
  -H "Authorization: Bearer <access-token>"
```
